# Documentación de dominio

Organización single-context:

- `CONTEXT.md` en la raíz: términos y modelo del dominio.
- `docs/adr/`: decisiones de arquitectura.

Antes de explorar código, leer `CONTEXT.md` y los ADR relevantes, si existen.
Si faltan, continuar: `domain-modeling` los creará cuando se resuelvan
términos o decisiones concretas.

Usar el vocabulario de `CONTEXT.md`. Señalar conceptos faltantes y cualquier
contradicción con un ADR existente, identificando la decisión afectada.
El código de la aplicación estará en `Plataforma/`.
